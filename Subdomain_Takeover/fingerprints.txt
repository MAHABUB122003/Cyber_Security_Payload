# Subdomain Takeover Fingerprints

## DNS side (find dangling CNAMEs)
```bash
# enumerate subdomains
subfinder -d target.com -silent | anew subs.txt
# resolve CNAMEs
while read d; do printf "%s -> " "$d"; dig +short "$d" CNAME | head -1; done < subs.txt | grep -v " -> $" | tee cnames.txt
# or one-shot with dnsx
dnsx -l subs.txt -resp-only -cname | grep -Ei "amazonaws|azurewebsites|github\.io|herokuapp|netlify|shopify|fastly|cloudfront|pantheon|bitbucket|surge|wordpress\.com"
```

## Node provider checks (quick loop)
```bash
dnsx -l subs.txt -cname -resp-only 2>/dev/null | awk '{print $2}' | cut -d. -f2- | sort -u
```
Then resolve each host to confirm it's dangling.

## Post-claim test (bounty proof)
1. Register the exact resource name on the provider.
2. `curl -s https://vuln.target.com/ | grep "your-content-marker"` → 200 + marker.
3. Screenshot, then delete your claim immediately.

## Automation tools
- subjack: `subjack -w subs.txt -t 100 -timeout 30 -o out.txt`
- tko-subs: `tko-subs -domains subs.txt -data providers-data.csv -output results.csv`
- can-i-take-over-xyz: reference fingerprint list + PoC videos

## Why it's a real bounty
A taken-over subdomain:
- Hosts phishing pages on a trusted domain
- Reads cookies scoped to the parent domain (session hijack)
- Bypasses same-origin / CSP allowances
- Malware hosting from a "trusted" hostname
