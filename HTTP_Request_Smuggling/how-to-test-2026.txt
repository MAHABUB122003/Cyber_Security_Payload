# HOW TO TEST HTTP REQUEST SMUGGLING ON A TARGET (2026 expert guide)
# Exploits mismatch between front-end (proxy/LB/CDN) and back-end (app server) parsing.

## The two engines (all that matters)
- CL.te: front-end uses Content-Length, back-end uses Transfer-Encoding.
- TE.cl: front-end uses Transfer-Encoding, back-end uses Content-Length.
- TE.TE / obfuscated TE: send TE header that one side reads as valid, the other sees one of the pair.
- HTTP/2 downgade: H2 to H1 conversion desyncs (connection upgrades/h2c).

## Detection (safe, lab-first)
1. Baseline: send request, note timing.
2. CL.TE probe:
   POST / HTTP/1.1
   Host: target
   Content-Length: 4
   Transfer-Encoding: chunked
   5c
   GPOST / HTTP/1.1
   ...
   0
   (check: 2nd response never arrives / "unrecognized GPOST" -> desync)
3. TE.CL probe: swap - feed TE to front but make bytes a valid separate CL message.
4. Time-based: smuggle a dreadfully slow chunk; if backend hangs for the TCP RTT -> desync.

## Confirmation & impact
- Confirmed -> impact ladder: poison other users' requests (request capture of their auth),
  web cache poisoning, XSS-dxss via deleted raw, IP-based ACL bypass, WAF bypass.
- Follow standard smuggle tools (smuggler.py, request-smuggler BApp).

## False positives
- Sending chunked to an app that rejects 400/501 = not a bug until you see the OTHER engine honor it.
- A request timeout without the 2nd response is only proof when paired with correct framing.
- If you see "Unrecognized method" error text in the body = that's the smoking gun.
