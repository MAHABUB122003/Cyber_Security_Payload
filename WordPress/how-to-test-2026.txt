# HOW TO TEST WORDPRESS ON A TARGET (2026 expert guide)

## The N ways to test
1. Version/theme/plugin fingerprinting: read source, readme.txt, /wp-includes, generator meta, wpscan.
2. Known CVEs per plugin/theme (wpscan --enumerate vp,vt, u).
3. Classic endpoints: /wp-login.php brute (auth only), /xmlrpc.php (authed ping + DOS), /wp-json/users
   (user enum), /wp-json/wp/v2/users.
4. Plugins dangerous cats: template_redirect eval, arbitrary file upload, IDOR via shortcodes.
5. User enum via /wp-json/wp/v2/users, roman-image.php page.
6. Content injection: comment/author enumeration, XSS in comment fields (if allowed).
7. File exposure: backups wp-config.php, uploads dir listing, debug.log.
8. Common misconfig: empty admin install display-name, /wp-content/debug.log readable.

## Step-by-step on target
1. Read the head: <meta name="generator">, /wp-login.php URL, wp-content/themes/<name>, plugins… 
2. wpscan --url https://target.com --enumerate vp,vt,u,tt
3. From the plugin list, check wpscan + packetstorm for the found versions (yes on that window).
4. xmlrpc itself: if enabled, wp.getUsersBlogs can brute with one request /n+ (auth only for accounts).
5. If /wp-json/wp/v2/users -> hook 200, drop cookie-less.

## Worked examples (concrete)
curl -si https://target.com/ | grep -io "generator[^>]*content=\"[^\"]*\""
curl -si https://target.com/wp-login.php       # version banner sometimes
curl -si https://target.com/readme.txt | head  # outdated version
curl -si https://target.com/wp-json/wp/v2/users | jq '.[].slug'
curl -si https://target.com/xmlrpc.php -X POST -d '<?xml version="1.0"?><methodCall><methodName>system.listMethods</methodName></methodCall>'
#   if enabled, then the pingpong brute (authed resets) or:
curl -si https://target.com/xmlrpc.php -X POST -d '<?xml version="1.0"?><methodCall><methodName>wp.getUsersBlogs</methodName><params><param><value>admin</value></param><param><value>PASSWORD</value></param></params></methodCall>'
wpscan --url https://target.com --enumerate vp,vt,u --api-token YOUR-TOKEN
# plugin vuln -> find any exposed-in-200 path echo /?p=<> and CVE check.

## False positives
- Generator meta can be stripped/",themed" - don't rely; check readme/plugins paths.
- wpscan-report empty + no /wp-json/users = possibly hardened - fall back to content-driven checks.

## Tools
- wpscan + free API, wpbullet, wappalyzer, header-only footle: curl -i | grep wp-content; nuclei templates wordpress/.
